# Valeo_SVMtrial 검증용 샘플 데이터

가상의 한글 8D 대책서와 5인 평가 시트입니다. 모든 회사명, 인명, 품번은 가상입니다.
Pass 규칙을 숨겨 두었으므로, 파이프라인이 그 규칙을 다시 찾아내는지로 동작을 검증합니다.

## 구성
```
data/raw/pdfs/대책서/CUST_A/   41개  A4 세로 '문서형', 흑백 스캔본(기울기·노이즈), 3~5쪽
data/raw/pdfs/대책서/CUST_B/   41개  16:9 '슬라이드형', 컬러 이미지 PDF, 9~11장
data/raw/labels/평가결과_long.xlsx   410행 (평가자 5명 × 82건, 권장 long 형식)
alt_formats/평가결과_wide.xlsx       같은 내용의 wide 형식 (형식 자동판별 테스트용)
tools/make_sample_data.py            생성 스크립트 (--n, --seed 로 재생성/확대)
_answer_key/                         ⚠️ 정답지 — 파이프라인 입력에 넣지 말 것
```
- 모든 PDF 페이지는 이미지 한 장이며 텍스트 레이어가 없습니다. 이미지 기반 전제 그대로입니다.
- 일부러 넣은 오류:
  - 결과값 표기가 섞여 있습니다(Pass/합격/P/OK, Fail/불합격/F/NG).
  - 빈칸 10개가 있습니다.
  - 평가 없는 PDF 2개와 PDF 없는 평가 2건이 있습니다.

## 사용법 (프로젝트 루트에서)
1. 이 zip의 `data/` 폴더를 프로젝트 루트 `valeo_svmtrial/data/`에 그대로 덮어씁니다. `_answer_key/`는 프로젝트 밖에 따로 둡니다.
2. Claude Code에 지시:
   ```
   data/raw 에 샘플 데이터를 넣었어. Phase 2~3 검증은 이 데이터로 하고,
   Phase 3 실호출은 CUST_A_001~003, CUST_B_001~002 다섯 건만 먼저 해줘.
   ```
3. 전체 실행 규모: 페이지 약 570장, 즉 Gemini OCR 호출 약 570회입니다. 먼저 `--dry-run`으로 확인하세요.
4. 결과가 나오면 `_answer_key/정답_README.md`의 채점 기준과 비교합니다.

## 참고: SETUP.md의 Phase 완료 기준과 다른 점
SETUP.md §12의 완료 기준은 그 문서 안의 영문 더미 생성기를 기준으로 쓰였습니다. 이 샘플로 검증할 때는 `_answer_key/정답_README.md`의 기준을 우선합니다.
- Phase 2: "PDF 80개" 대신 **82개, 매칭 오류 4건**
- Phase 4: "rater_E가 가장 엄격" 대신 **평가자D가 가장 엄격, 평가자E는 서명란 의존**

## 재생성 / 확대
```bash
python tools/make_sample_data.py --out sample_data_n80 --n 80 --seed 11
```
Ubuntu에 한글 폰트가 없으면 `sudo apt install fonts-nanum`을 실행하거나, `--font <ttf 경로>`로 지정하세요.
같은 규칙으로 300회 시뮬레이션한 결과, 그룹당 문서 수에 따라 각 요인을 잡아낼 확률(q<0.1)은 다음과 같습니다. 실데이터 수집 목표를 정할 때 참고하세요.

| 그룹당 문서 수 | 5Why(강) | 그래프(중강) | 수평전개(중) | 사진(약) | 미끼(오탐) |
|---|---|---|---|---|---|
| 40건 | 44% | 31% | 13% | 0% | 2% |
| 80건 | 92% | 79% | 34% | 9% | 3% |
