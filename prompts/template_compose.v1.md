통계로 검증된 결과를 준다. 이것으로 **표준 문서 템플릿 명세**를 작성하라.

- `skeleton`: Pass 문서에서 구한 섹션 골격(존재율, 중앙 순서, 권장 분량, 대표 표 열 구성)
- `concepts`: 등급(`확정`/`유력`/`참고`)과 효과 통계가 붙은 개념
- `global_hints`: 문서 전체 규칙 후보
- `rater_conflicts`: 평가자 간 요구가 충돌하는 항목

## 반드시 지킬 것
1. **실제 내용을 쓰지 않는다.** 가짜 수치, 가짜 원인, 가짜 대책을 절대 쓰지 않는다.
   플레이스홀더만 쓴다. 예: `[예: 불량률 추이 그래프 — 대책 전/후 ppm]`
2. **모든 `Section` 과 `Element` 에 `evidence_ids` 를 넣는다.** 값은 개념 ID(`C012` 등) 또는 `"skeleton"` 이다.
   비어 있으면 검증 실패로 되돌려진다.
3. `required` 는 등급이 `확정` 인 개념에서 나온 요소에만 true 로 한다.
4. `guidance` 는 **작성자에게 주는 지시문**이다. `[작성 가이드]` 로 시작하고 한국어로 쓴다.
   가능하면 근거 통계를 한 구절로 덧붙인다. 예: `(근거: 있을 때 Pass율 86% vs 없을 때 31%)`
5. 섹션 순서는 `skeleton` 의 중앙 순서를 따른다.
6. `등급 = 참고` 인 개념은 `required=false` 로 넣거나, 넣지 않는다. `기각` 은 절대 넣지 않는다.
7. 통계 값(`presence_in_pass` 등)은 주어진 값을 그대로 옮긴다. 새로 만들지 않는다.
